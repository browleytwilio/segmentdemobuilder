# DEPRECATED: GET /auth/callback

<Warning>
  This route no longer exists. Authentication is now handled by Clerk. The `/auth/callback` OAuth exchange has been replaced by Clerk's built-in auth flow. See [Authentication](/guides/authentication) for the current auth architecture.
</Warning>

The following documents the previous behavior for historical reference.

---

## Previous Behavior

Handled the OAuth callback after a user authenticated with Google or GitHub. Exchanged the authorization code for a Supabase session and redirected to the dashboard.

### Request

```bash
GET /auth/callback?code={authorization_code}
```

**Authentication:** Not required (this endpoint established the session)

**Query Parameters:**

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `code` | string | Yes | Authorization code from the OAuth provider |

### Flow

1. Extracted the `code` query parameter
2. Called `supabase.auth.exchangeCodeForSession(code)` to establish a session
3. Set a short-lived cookie `x-analytics-identify` (30-second TTL) to trigger client-side `analytics.identify()` after the redirect
4. Redirected to `/dashboard`

### Error Handling

If the `code` parameter was missing or the exchange failed:

```
302 Redirect -> /login?error=auth-code-error
```

### Replacement

Authentication is now handled by Clerk at `/sign-in` and `/sign-up`. Profile creation is handled by the [Clerk webhook](/reference/api/webhooks-clerk). Analytics identification is handled directly in the `AnalyticsProvider` component using Clerk's user data.
