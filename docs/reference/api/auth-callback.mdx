# GET /auth/callback

Handles the OAuth callback after a user authenticates with Google or GitHub. Exchanges the authorization code for a Supabase session and redirects to the dashboard.

## Request

```bash
GET /auth/callback?code={authorization_code}
```

**Authentication:** Not required (this endpoint establishes the session)

**Query Parameters:**

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `code` | string | Yes | Authorization code from the OAuth provider |

## Flow

1. Extracts the `code` query parameter
2. Calls `supabase.auth.exchangeCodeForSession(code)` to establish a session
3. Sets a short-lived cookie `x-analytics-identify` (30-second TTL) to trigger client-side `analytics.identify()` after the redirect
4. Redirects to `/dashboard`

## Error Handling

If the `code` parameter is missing or the exchange fails:

```
302 Redirect → /login?error=auth-code-error
```

The login page displays an error message when the `error` query parameter is present.

## Analytics Cookie

The `x-analytics-identify` cookie exists solely to bridge the server-side OAuth redirect with client-side analytics identification. The `AnalyticsProvider` component checks for this cookie on mount:

1. If the cookie exists, it calls `analytics.identify()` with the user's ID and traits
2. The cookie is then deleted (it has a 30-second TTL as a safety net)

This ensures the user is properly identified in Segment after OAuth login, even though the actual auth exchange happens server-side.
